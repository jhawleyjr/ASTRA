# Lessons (append-only)

Numerical, build, and tooling gotchas that actually bit us. One entry each; newest at the bottom. If a lesson turns into a rule, it goes in CLAUDE.md and the entry here says so.

- **2026-09-14 — git from a Cowork session leaves `.git/index.lock` behind.** The Cowork shell mounts the repo without delete permission, so any git command that touches the index (`git status` without `--no-optional-locks`, `git add`, `git commit`) can leave a zero-byte `index.lock` it cannot remove, and the next commit fails. Rule: in Cowork, only read-only git with `git --no-optional-locks`, and never commit from there — commits belong to Claude Code sessions (see `docs/process/workflow.md`).
- **2026-09-14 — ROS `PYTHONPATH` leaks into the venv.** `source /opt/ros/*/setup.bash` in `.bashrc` exports `PYTHONPATH`, which a venv still honors; pip then reports ROS packages' missing deps as errors (harmless) and, worse, ROS site-packages can shadow venv packages. Rule: `unset PYTHONPATH` in any ASTRA shell; `scripts/setup-ubuntu.sh` does it for its run and the `justfile` must export an empty `PYTHONPATH` so `just check` is immune.
- **2026-09-14 — PreToolUse hooks added to `.claude/settings.json` take effect in the running session, not the next one.** The oracle guard (`guard-oracle.sh`) fired on the very Bash command that was committing it, because the Bash matcher inspects the *command text*: a commit message or `echo` that names a guarded directory next to a redirect (`2>/dev/null` counts) is blocked. Rule of thumb: keep guarded path names out of commit messages and shell one-liners; put long commit messages in a scratchpad file and use `git commit -F`.
- **2026-09-14 — the guard-oracle Bash matcher was wrong in both directions.** It anchored guarded paths to start-of-string or `/`, so relative-path writes mid-command (`> tests/golden/x.csv`, `rm docs/decisions/…`) passed, while it blocked commands that merely *named* a guarded directory next to `2>/dev/null`. Fixed to match only a guarded path in a write-target position (after `>`/`>>`, `tee`, `sed -i`, `rm/mv/cp/touch/truncate`, `git rm/mv/checkout/restore`), with a 15-case probe. The earlier rule of thumb ("keep guarded path names out of commit messages") is retired: when a hook misfires, fix the hook, don't route around it.
- **2026-09-14 — a tool that rewrites `.claude/settings.json` drops keys it doesn't know about.** The `attribution.sessionUrl=false` setting added mid-session was lost when the oracle-guard hook was added, and the next commit carried a session URL. Rule: after any edit to `settings.json`, `git diff` it before committing; `attribution.sessionUrl` must stay `false`.
- **2026-09-14 — edits made in the main checkout are invisible to a `--worktree` session.** A worktree branches from remote `main`; anything uncommitted in `~/repos/ASTRA` itself (a reviewer's fix, a hand edit) is not there. Rule: commit working-tree changes on the current branch before starting a worktree session, or put the instruction in the opening prompt instead of leaving a dirty file.
- **2026-09-14 — nanobind's stub generator never emits `__version__`.** `stubgen.py` has a fixed skip list of module dunders (`__version__`, `__spec__`, `__loader__`, ...), so `m.attr("__version__")` exists at runtime but not in `_core.pyi`, and pyright strict then fails on every use. Rule: the module exposes `VERSION`; `python/astra/__init__.py` re-exports it as `__version__`.
- **2026-09-14 — an unnamed `nb::exception<T>(m, "Name", base)` temporary fails the gate.** clang-tidy's `bugprone-unused-raii` and `bugprone-throw-keyword-missing` both fire on it (the type name contains "exception"). Name the objects (`[[maybe_unused]] const nb::exception<...> x(...)`); they exist for the constructor's registration side effect. The scratch probe missed this because it ran clang-tidy outside the compile database; only `just tidy` over `build/python` is the check.
- **2026-09-14 — a backgrounded `just check > log; echo EXIT=$?` reports the wrapper's exit, not the gate's.** The task notification said "exit code 0" while the log ended in `Recipe tidy failed`. Rule: when the gate runs in the background, read the `EXIT=` line (or `check: OK`) from the log before calling anything verified.
- **2026-09-14 — `ruff format` formats Python fences inside Markdown.** `ruff format --check .` graded every `.md` in the tree (25 files for 4 `.py`), so a non-black snippet in an ADR would break the gate, and `just format` would rewrite human-owned `docs/decisions/**` without the oracle guard ever seeing a path. Rule: `*.md` is in ruff's `extend-exclude` in `pyproject.toml`; the formatter touches only `.py` and `.pyi`.
- **2026-09-14 — `fable` at `xhigh` with inheriting subagents cost ~$300 API-equivalent in one day of M0.** Measured from the transcripts: 3.7M output and 100M cache-read tokens; one built-in `/code-review` run alone was 26 agents, 320k output, 34M cache reads. Fable is 2x Opus on both price and Max-plan burn and is capped at 50% of the weekly limit; higher effort is ~7x the tokens. Rule (now in CLAUDE.md and workflow.md §Model and effort): `opusplan` at `high`, subagents on Sonnet, review on Codex, build output to a file not the context; escalate model or effort per session only when a failure shows it was needed, never as a standing setting.
- **2026-09-14 — the `--worktree` session's Bash guard refuses more than git.** It rejected a heredoc file write followed by any other command, a Python heredoc whose text mentioned a shell variable, and `printf '<json>' | hook.sh` ("input assembled by the command"). Rule: in a worktree session, create and edit files with the Write and Edit tools, put a hook's stdin JSON in a scratchpad file and redirect it in, and run each `git` command on its own line.
- **2026-09-14 — a build started in the background in the same response has not always spawned when the next command runs.** The Stop hook's busy-tree guard returned 0 once against a "concurrent" build that did not exist yet. Rule: probe the guard with a process that is certainly there, `just --working-directory <tree> --justfile <stub with a sleeping recipe> slow` in the background, and only then run the hook.
- **2026-09-14 — a human-owned golden header can carry an uncaught clang-tidy violation for milestones, because nothing had ever included it in a compiled TU.** `tests/golden/frames/adr0001_cases.hpp` was declared "clang-tidy clean" when it merged (PR #12), but clang-tidy only analyzes headers actually pulled into a translation unit; M1 PR 1's `frames_test.cpp` was the first thing to include it, and its `C_nb` member (Stevens & Lewis DCM notation) then failed the repo's `lower_case` member rule. Rule (already in CLAUDE.md/workflow.md): this is a stop-and-ask for Joe, never a loosened filter or a self-authorized edit; Joe armed `touch-goldens` and the fix was one `NOLINTNEXTLINE(readability-identifier-naming)` comment, no values touched.
- **2026-09-14 — an unexpected mid-session change to `CLAUDE.md`/`STATE.md`/`docs/process/workflow.md` was Joe editing the same worktree checkout via Cowork concurrently, not a review tool writing outside its mandate.** The session's first hypothesis (that the just-run `/codex:adversarial-review` subprocess, which has its own Bash access, had patched process docs despite being documented review-only) was wrong. Rule: an unexplained working-tree change mid-session is worth asking about before treating it as a tool malfunction — Joe's own concurrent edits are a normal source.
- **2026-09-14 — `/codex:review`, `/codex:adversarial-review`, and `/wrap` default to `disable-model-invocation: true`, so a session cannot run them via the Skill tool.** The first two are thin wrappers around `codex-companion.mjs`; a session can call that script directly with `Bash` (`node <plugin>/scripts/codex-companion.mjs review --base origin/main --wait`, `... adversarial-review --base origin/main`) instead of waiting for Joe to type the slash command. Became a rule: Joe removed `disable-model-invocation` from `.claude/skills/wrap/SKILL.md` and added lines to `CLAUDE.md` saying the session runs review and `/wrap` itself.
- **2026-09-14 — reassigning a `YAML::Node` handle with `operator=` while walking a document corrupts the document, not just the local variable.** `Config`'s dotted-path lookup (M1 PR 2) walked a path with `current = child(current, segment)` in a loop; yaml-cpp's `Node::operator=` exists to support `node["key"] = value` document-*building* and mutates the node the handle already pointed at in place, so each reassignment silently rewrote the shared document one level deeper — `config.number("sim.dt")` first worked, but every *later* lookup on the same `Config` (or on any `Config` sharing that document) then failed with `YAML::InvalidNode: invalid node; this may result from using a map iterator as a sequence iterator, or vice-versa`, reproducing outside GoogleTest with a 3-line yaml-cpp-only program. Rule: never assign into a `YAML::Node` variable that already aliases a meaningful node; walk by copy-constructing a *new* `const YAML::Node` at each step (recursion, or a fresh variable per level) instead of reusing one via `=`. `core/src/config/config.cpp`'s `navigate_from` does this.
- **2026-09-14 — `.github/workflows/check.yml`'s apt install line and `scripts/setup-ubuntu.sh`'s were two copies of the same package list, and M1 PR 2 (yaml-cpp) only updated one.** PR #16's CI run failed on a missing `libyaml-cpp-dev` that the local `just check` never caught, because the developer machine already had it from `setup-ubuntu.sh`. Rule: there is now one list — `scripts/setup-ubuntu.sh --ci` runs only the `apt-get install`, and the workflow calls that instead of its own `apt-get` line. Adding a package means editing `setup-ubuntu.sh` once; CI picks it up automatically.
- **2026-09-14 — a bare `YAML::Node{}` is not "undefined" in yaml-cpp, so `Config`'s not-found sentinel silently lied.** `Config::navigate`'s `child()` helper (M1 PR 2) returned `YAML::Node{}` for "not a map" and "index out of range". A default-constructed `YAML::Node` is *Null*-typed but still reports `IsDefined() == true` — genuine "missing key" semantics only come from subscripting a real (even empty) map/sequence for a key that isn't in it. So navigating a dotted path *through* a scalar with more segments after it (`config.number("physical.gravity.g", default)` when `physical.gravity` is a bare plugin-path string, §13's scalar form) did not stop at the scalar as intended: `navigate_from`'s `!next.IsDefined()` check never fired, recursion continued on the Null-but-"defined" node, and the final read threw `ConfigError: expected a number value` instead of returning the default — reproduced outside GoogleTest with a 3-line yaml-cpp-only program (`kEmptyMap["nonexistent"]` correctly gives `IsDefined() == false`; `YAML::Node{}` does not). No earlier PR hit this because nothing before M1 PR 3 had an optional field on a model whose own config slot could be a bare scalar. Rule: `child()`'s two not-found branches return `empty_map[key]` (an explicit local `YAML::Node{YAML::NodeType::Map}` subscripted for a name that can't collide), never a bare `{}`; `tests/unit/config/config_test.cpp`'s `NavigatingPast...IsUndefined` tests pin this.
- **2026-09-15 — `nohup <cmd> > log 2>&1 &` inside a Bash call already run with `run_in_background: true` double-backgrounds the command, and the tool's "completed" notification then reports the wrapper shell's near-instant exit, not the long command's.** `just check` (several minutes) was launched this way twice in M1 PR 4; each time the notification arrived in under a second while `just` kept running for minutes afterward, and the Stop hook's busy-tree guard (correctly) blocked the turn from ending in the meantime. This sharpens the existing rule (2026-09-14, "a backgrounded `just check` reports the wrapper's exit, not the gate's"): the fix is not just reading `EXIT=`/`check: OK` from the log, but never nesting a second backgrounding mechanism (`nohup ... &`) inside the harness's own `run_in_background`. Use the tool's backgrounding alone, find the real command's pid (`ps`/`pgrep`), and block on that pid directly (`tail --pid=<pid> -f /dev/null`) before trusting the log.
- **2026-09-15 — editing a tracked file after `just check` has started, but before its `format-check`/`tidy` stage runs, makes that stage grade the edit the earlier build/test stages never saw.** A doc-comment fix (responding to a Codex adversarial-review finding) landed mid-run; `format-check` correctly failed on the unformatted comment, costing a full extra `just check` cycle (all four presets rebuild+retest) to rerun. Rule: once `just check` is launched, don't edit tracked C++/Python files until it finishes (or has clearly failed) — `just format` immediately followed by a fresh `just check` is cheaper than editing into a run already in flight.
- **2026-09-15 — for an oblate ellipsoid, the meridian radius of curvature M(lat) is always ≤ the prime-vertical radius N(lat) (equal only at the poles: M/N = (1-e²)/(1-e²sin²(lat)) ≤ 1), so bounding an altitude floor against N(lat) alone is wrong.** M2 PR 1's `wgs84_rotating::validate_p_n` rejected `alt <= -N(lat)`, but `p_n_dot`/`omega_en_n` also divide by `(M(lat) + h)`; an altitude in `[-N(lat), -M(lat)]` (e.g. the equator's ~43 km gap between the two) passed validation while already making that denominator non-positive. Caught by Codex code review, not by any test written before it — the existing tests only checked N(lat)'s own boundary. Rule: when two related radii/bounds both gate the same denominator, validate against whichever is more restrictive at every latitude, not the one that happens to be easiest to reach for.
- **2026-09-15 — two plugins that each read their own "radius" from config (an `EarthModel` and a paired `GravityModel`) can independently pass their own init-time validation while still dividing by zero together.** M2 PR 1's `earth/round` and `gravity/inverse_square` each validate altitude against *their own* configured radius; a config with earth radius 3000 m and gravity radius 2000 m accepts altitude -2000 m at earth's floor while gravity's `g_n()` divides by exactly zero at that same altitude (Codex adversarial review). Rule: a position-representation-compatibility check (same units/meaning) is not the same guarantee as a geometry-compatibility check (same numbers); when two independently-configured models both derive singular behavior from the same state, each needs its own `validate_p_n`-style init-time check of its own math, not just of the state's units.
- **2026-09-15 — a geodetic (lat, alt) pair can pass an Earth model's own altitude floor while still collapsing a *different* plugin's derived geometry to near-zero.** `wgs84_j2`'s J2 gravity formula converts (lat, lon, alt) to ECEF and divides by the resulting radius from Earth's center; near the polar margin, `lat = kMaxLatitude, alt = -N(lat)*(1-e²)` passes `wgs84_rotating`'s own `M(lat)`-based floor (a one-dimensional bound) while collapsing the *3D* ECEF radius to ~0.043 m, because the singularity there is a combination of near-polar latitude and altitude, not a simple altitude floor. Verified numerically (Python) before writing the fix — trust but check any "surely this other check already covers it" reasoning about a different plugin's math. Rule: `validate_p_n` overrides must check the actual expression a plugin's own math divides by, not assume a sibling plugin's unrelated bound transfers.
- **2026-09-15 — `tan()`/`1/cos()` evaluated at a double's nearest representation of π/2 is enormous but never exactly `Inf`, and the exact magnitude is not portable across optimization levels.** A test asserting `p_n_dot` becomes non-finite at `lat = pi/2` failed: `cos(pi/2 as double) ≈ 6.1e-17` (never exactly zero, since π/2 is irrational), giving a huge *finite* reciprocal — 1.63e16 under one preset's libm, 2.56e11 under another's (observed across debug vs. release). Rule: never assert non-finiteness from a trig singularity approached only through a double's rounding of an irrational boundary; assert a magnitude threshold instead, set at least several orders of magnitude below the smallest value observed across every preset, not tuned to one build.
- **2026-09-15 — NASA/TM-2015-218675 (the M2 NESC check-case source) publishes exact initial conditions per case but, by explicit editorial choice, no single numeric reference trajectory or fixed tolerance — it presents comparison plots across independently-run tools instead ("Known Risks and Mitigations", Volume I).** Assumed before reading the report that "the tolerances the NESC data provides" (docs/architecture.md §16) meant a number in the document; it doesn't, for any case. Rule for PR 3's full ten-case harness: budget for an independent high-precision integration (or a stated cross-tool comparison band) as the oracle for each case, not a lookup into the report's own tables.
- **2026-09-15 — `(cmd; echo EXIT=$?) & disown` inside a Bash call already run with `run_in_background: true` double-backgrounds exactly like the previously-documented `nohup ... &` case, and the tool's "completed" notification again reported the wrapper's near-instant exit while the real `just check` kept running for minutes.** M2 PR 1b hit this twice before catching it via the Stop hook's busy-tree guard. Sharpens the existing rule again: the bug is combining the harness's own backgrounding with *any* shell-level backgrounding construct in the same call (`&`, `disown`, `setsid`, `nohup`), not specifically `nohup`. Pass the bare foreground command to `run_in_background: true` and find/block on the real pid (`pgrep`, then `tail --pid=<pid> -f /dev/null`) afterward.
- **2026-09-15 — clang-tidy's `NOLINTNEXTLINE` suppresses a finding only on the literal next source line, not the next non-comment statement.** A multi-line justification comment placed *before* `NOLINTNEXTLINE` pushed the actual `if` three lines further down; the suppression comment compiled fine but did nothing, and the warning still fired at `just check`'s `tidy` stage (two wasted full-tree tidy runs, M2 PR 1b). Rule: `NOLINTNEXTLINE` must be the line immediately above the flagged statement; put any longer justification comment above *that* line, never between the NOLINT comment and the code it's meant to cover.
- **2026-09-15 — clang-tidy's `readability-simplify-boolean-expr` rewrite of `!(a >= min && a <= max)` to `a < min || a > max` is not NaN-safe.** For NaN, `a>=min` and `a<=max` are both false, so the original negated conjunction is `true` (correctly treating NaN as "outside range"); the "simplified" disjunction is `false` for the same NaN (since `a<min` and `a>max` are each false too), silently treating NaN as "in range" instead. Caught only by working out the NaN row of the truth table by hand, separately from the boolean-algebra derivation that makes the rewrite look obviously correct (M2 PR 1b, `AtmosphereModel::at()`'s range check). Rule: never accept this class of clang-tidy suggestion on a floating-point range check without checking its NaN behavior explicitly; add a `NOLINTNEXTLINE` with the NaN reasoning instead.
- **2026-09-15 — Codex's `review`/`adversarial-review` scripts diff the working tree against a base ref with plain `git diff`, which never shows untracked files.** M2 PR 1b's first `review` call, run before any commit, reported only the changes to already-tracked files and missed every new file (a whole new interface, plugin, and test suite) entirely — Codex itself caught this ("the tracked patch references files... not included in it") rather than silently approving a partial diff. Rule: `git add -A` and commit (not just stage) before the first Codex review call of a session that adds new files, or the review covers only part of the change.
- **2026-09-15 — NASA-TM-X-74335 / NOAA-S/T 76-1562's Table I prints adjacent page-pairs covering the *same* nominal altitude band under two different primary index columns: one page titled "Geopotential Altitude" tabulates round H values with derived Z; the facing page titled "Geometric Altitude" tabulates round Z values with derived H (H<Z always for positive altitude, via H=r0·Z/(r0+Z)).** A first low-DPI read swapped which printed column was H and which was Z on one page, and two pages showing overlapping altitude ranges briefly looked like a duplicate-page rendering bug rather than the document's actual structure, before a 600 DPI re-crop of the column headers resolved it. Rule: read a source table's own column headers at high enough resolution to be unambiguous before trusting a transcribed value, and treat two pages with overlapping ranges as a hint to check for a second indexing convention, not as a rendering artifact.
- **2026-09-15 — diagnosing a numeric disagreement by reusing a source document's own printed, rounded intermediate value (instead of recomputing that intermediate fresh, the way the code under test actually does) adds a spurious extra noise source and can falsify a real mechanism that isn't actually wrong.** M2 PR 1b's transcribed-row tolerance derivation used `TranscribedRow.geopotential_h_m` (the document's printed H, rounded to the nearest metre) to compute each row's layer and test whether a per-layer accumulated-rounding mechanism explained the residuals; every row appeared to violate it, including one (Z=11000) whose zero-predicted-margin case looked conclusively disproven. Recomputing H fresh from Z via `geopotential_from_geometric()` — what the plugin and the generator's own `compute_row()` both actually do — showed the mechanism holds, with real margin, for 7 of 8 rows; only Z=11000 was a genuine anomaly. Rule: when comparing a document's transcribed value against a fresh computation, drive every step of that comparison through the same code path the real computation uses, not through a shortcut that reads a different (independently rounded) column of the same source.
- **2026-09-16 — the oracle guard's `touch .claude/touch-goldens` marker was resolved against `CLAUDE_PROJECT_DIR`, which in a worktree session is the worktree, so touching it in the main checkout armed nothing — and every golden-touching PR runs in a worktree.** Three golden-writing PRs (M1 PR 1, M2 PR 1, M2 PR 1b) each hit the block and it read as the guard demanding to be re-armed over and over; the marker in `~/repos/ASTRA/.claude/` was never the file `guard-oracle.sh` was looking at, because `.claude/` is tracked and each worktree checks out its own copy. The `ASTRA_TOUCH_GOLDENS=1` escape had the same shape of failure for a different reason: hooks inherit the `claude` process's environment, so an `export` (or a `Bash` tool call) inside a running session never reaches the hook — it only works on the launch line. Rule: `guard-oracle.sh` accepts the marker in the session's own root **or** in the main checkout, resolved with `git rev-parse --git-common-dir`; `disarm-goldens.sh` (SessionStart) deletes both, so a main-checkout marker cannot silently disarm the guard forever. `.claude/hooks/tests/guard-oracle.cases` pins all four combinations against real `git worktree`s via the `$ROOT_WT_ARMED` / `$ROOT_WT` placeholders. Generalization worth keeping: when a hook resolves a path against a session-provided root, test it in the layout the session actually runs in, not only in the repo root where it was written.
- **2026-09-16 — a reference member (e.g. `EarthModel&`) does not propagate the enclosing object's `const`-qualification to the referent, so a `const` method can still call a non-`const` method through one.** M2 PR 2's plan-mode design argued `Eom::operator() const noexcept` structurally could not call a hypothetical non-`const` `WindModel::wind_n` because `Eom` holds `EarthModel&`/`GravityModel&` reference members — plausible-sounding, and wrong: verified directly (`struct Holder { Mutable& ref_; void f() const { ref_.non_const_method(); } };` compiles). Only *direct, non-`mutable` data members* actually become `const`-qualified inside a `const` method; a reference or pointer member's constness does not extend to what it refers to (unlike a pointer *member itself*, which does become `T* const`, but still permits mutating `*p`). Caught by Codex's plan-review round before any code was written. Rule: never reason "the caller is `const`, so it can't call a non-`const` method on a reference/pointer member" without checking — the real guarantee, if one is needed, has to come from the *callee's own* constness, not the caller's.
- **2026-09-16 — `pgrep -x just` can return more than one pid for a single `just check` invocation (a leftover `just` process from an unrelated, already-finished earlier call still exiting, at least once observed), and separately `ps aux | grep "just check"` also matches the harness's own `/bin/bash -c 'eval ... just check ...'` wrapper line, since the literal text "just check" appears inside its `eval` argument even though the process itself is named `bash`, not `just`.** M2 PR 2 blocked on a decoy pid via `tail --pid=<wrong-pid> -f /dev/null`, which returned almost instantly while the real `just check` kept running for minutes; a second attempt, filtering `ps aux` output for the line whose command is exactly `just check` (not `bash -c ...`), found the right pid. Distinct from the already-documented `nohup`/`disown` double-backgrounding lessons (no extra backgrounding was used here). Rule: after `run_in_background`, don't trust the first or lowest pid `pgrep`/`grep` returns; cross-check against `ps aux`'s full command column for a line whose command is exactly `just check`, excluding any `bash -c` wrapper, and re-verify the chosen pid is still alive immediately before blocking on it.
- **2026-09-16 — "this looks like the same disclosure-only shape as an already-decided gap" is not itself a check, and got a null-pointer bug wrong.** M2 PR 2's Cowork re-review round asked whether `Simulation::for_testing` (a test-only factory) should validate its inputs the way `from_config` does; several checks (position-representation, `validate_p_n`, the atmosphere `valid_range` check) were correctly left unenforced, since a test that needs an otherwise-invalid state to reach `step()` is a legitimate use, and no test happens to fly near any of those boundaries today. A non-null `wind` paired with a null `earth` was reflexively filed under the same reasoning and left unenforced too — but that one is not "produces a plausible-but-domain-wrong answer if nobody hits the boundary"; `Simulation::step`'s wind branch dereferences `earth_` *unconditionally* whenever `wind_` is non-null, inside `step()`'s own `noexcept`, so it is a guaranteed crash the moment `step()` runs at all, not a boundary condition. A second adversarial-review pass on the same fix caught the wrong call before merge. Rule: before leaving an input-validation gap disclosed-only by analogy to another already-decided gap, check whether the failure mode is actually the same kind — "plausible wrong answer only past some domain boundary" is a real reason to defer; "unconditional null/UB reachable through the ordinary call path" is not, no matter how much the code shape resembles a case that was correctly deferred.
- **2026-09-16 — `constexpr` on a function already implies `inline`, so `inline constexpr double f(...)` on a *function* is a clang-tidy `readability-redundant-inline-specifier` error under this repo's `WarningsAsErrors: '*'`, even though the identical `inline constexpr` on a *variable* (`inline constexpr double kFoo = ...`, the geodesy.hpp/frames.hpp pattern) is correct and still needed there to avoid an ODR violation across TUs.** M2 PR 2b's `core/util/units.hpp` copied the variable pattern onto its four conversion functions and failed `just check`'s `tidy` stage on all four. Rule: for a header-defined `constexpr` *function*, drop `inline`; for a header-defined `constexpr` *variable*, keep it — the two look identical but the rule is opposite depending on which kind of declaration it is.
- **2026-09-16 — a `double` loop counter fails clang-tidy's `clang-analyzer-security.FloatLoopCounter` under `WarningsAsErrors: '*'`, even in a test file, even when every value used is a round power-of-ten multiple with no accumulated-rounding concern in practice.** M2 PR 2b's Lyapunov-residual sweep (`for (double y = 1e-8; y <= 10.0; y *= sqrt(10))`) failed `tidy` on exactly this. Rule: drive a geometric/log-spaced sweep from an integer step count (`y = 1e-8 * std::pow(10.0, step / 2.0)` for `int step`) instead of a floating-point multiplicative loop variable, even where the multiplication itself would have been numerically fine.
- **2026-09-16 — releasing a `unique_ptr`'s raw pointer *before* calling a function that can throw (`wind->init(...)`, `ConfigError` on a bad config) leaks the pointee if that call actually throws, because nothing owns it during the exception's unwind.** M2 PR 2b's `dryden_test.cpp`/`dryden_psd_test.cpp` test helpers called `loaded.model.release()` to get a raw `WindModel*`, then called `->init(...)` on it, then wrapped the raw pointer in a new `unique_ptr` to return — every one of the plugin's own config-rejection tests (missing `seed`, negative `w20_knots`, etc.) leaked the model, caught by asan/lsan (`ZeroHeapAllocations`-style tests didn't catch it; only the leak-checked config-rejection tests did, since those are the ones that actually throw).
